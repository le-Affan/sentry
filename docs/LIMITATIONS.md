# Limitations

*Last updated 2026-08-27.*

Every limitation identified across this project, in one place, each with the evidence
behind it. For each: **what it limits**, and **what remains valid despite it**.

Read this before writing any claim about Sentry.

---

## 1. The synthetic-telemetry loop

**Evidence.** A bag of `event_type` 1–3 grams — no description text, no entity names,
nothing but the sequence of event-type values — recovers the technique for **89.8%** of
blobs against a **17.4%** majority-class baseline (`TEMPLATING_DESIGN.md` §7.1). On
truncated blobs it still scores 54.6% against 17.2%. Leakage is *worse* on untruncated
chains, so it is intrinsic to the skeleton design rather than an artifact of the token
budget.

Every event row, hostname, IP address, file path, hash, and timestamp in every blob was
invented by `src/templater.py`. VCDB contains no telemetry: across 10,596 records, IPv4
addresses appear in 4, SIEM-style hostnames in 3, event-level timestamps in 1, and
Windows file paths in none (`DATA_SURVEY.md` §3.2). The technique label and the event
chain are both derived from the same field, `action.*.variety`.

**What it limits.** The 90.0% technique-ID accuracy cannot be separated from this
structural leak. It must **never** be reported as a detection result or as evidence the
model can identify techniques in real telemetry.

**What remains valid.** Format adherence, ROUGE-L, BERTScore, and grounding are unaffected
— a model cannot infer a coherent summary, a correct asset list, or a plausible root
cause from an event-type histogram. `SCOPE.md` §5 already files technique accuracy as a
secondary compliance metric for this reason.

## 2. Teacher-model ceiling

**Evidence.** All 400 reference reports were generated by `gemini-3.1-flash-lite`
(`src/generate_reports.py`). The fine-tuned model is scored on agreement with those
references.

**What it limits.** Sentry cannot exceed its teacher. ROUGE-L 0.5104 and BERTScore 0.9102
measure similarity to Gemini's output, not correctness in any absolute sense. Systematic
errors in the teacher are invisible to every metric in `EVAL_RESULTS.md`.

**What remains valid.** The claim that a 3B model can be adapted to reproduce a larger
model's structured-reporting behaviour on this task, at 100% format adherence. That is a
distillation result, and it is what the numbers support.

## 3. Hand-curated technique lookup

**Evidence.** `labels/technique_lookup.yaml` is 21 rows written by this project, mapping
VERIS action varieties to single ATT&CK techniques. Nine rows are marked
`confidence: medium` and three `confidence: low`.

The official VERIS→ATT&CK crosswalk was evaluated and rejected: all 1,255 substantive
rows carry `mapping_type: related-to` with an empty `score_category`, giving a median
fan-out of 2 techniques per variety and a maximum of 115. Applied to VCDB, 4,270 records
have a mappable action but only **15** resolve to exactly one candidate
(`DATA_SURVEY.md` §3.3).

**What it limits.** Technique accuracy measures agreement with *our table*, not with
ground truth. Its ceiling is our curation quality, and a systematic error in the table
becomes a systematic error in the metric that no measurement here would detect.

**What remains valid.** The labelling is transparent and auditable — every row carries a
rationale and a confidence mark, and `src/label_coverage.py` validates every ID against
the pinned ATT&CK 19.2 bundle, failing on any revoked or misnamed entry.

## 4. Severity class imbalance

**Evidence.** Across 400 reports: Low 15 (3.8%), Medium 8 (2.0%), High 264 (66.0%),
Critical 113 (28.2%) — a **66.0% majority-class baseline**, with 94% of the corpus
High-or-Critical and only 8 Medium examples (`DATASET_STATS.md` §1).

**What it limits.** Severity accuracy is weakly informative. The tuned model's 82.5% is
only **+16.5 points** over always answering "High". Per-class performance on Low and
Medium is not measurable at these counts.

**What remains valid.** The comparison is still meaningful in *direction*: the base model
scored 47.5%, which is **below** the majority baseline, so the adapter moved the model
from worse-than-guessing to meaningfully better than guessing.

## 5. No real-telemetry evaluation

**Evidence.** Both `train.jsonl` and `test.jsonl` come from the same generator. No real
SIEM export was ever fed to the model.

**What it limits.** Nothing here supports a claim about performance on production
telemetry. The test split shares the generator, entity vocabulary, and chain skeletons of
the training split, so it measures generalisation *within* the synthetic distribution
only.

**What remains valid.** Held-out performance within that distribution is genuine — the 40
test incidents were never trained on, and the split is stratified by technique.

---

## 6. Single training run, no hyperparameter sweep

**Evidence.** `SCOPE.md` §6 fixes a single run. One configuration was trained: r=16,
α=32, dropout 0.05, LR 2e-4, cosine, 3 epochs, effective batch 8. 63 steps in 258.3
minutes on a Tesla T4. No sweep, no seed variation, no ablation.

Eval loss fell 1.3993 → 1.1387 → 1.1024 across the three epochs while train loss fell to
0.9748. Epoch 3 gained 0.036 on eval against 0.17 on train — the opening train/eval gap
of early overfitting on 324 training examples.

**What it limits.** No claim that these hyperparameters are optimal, and no error bars on
any reported number. A single run cannot distinguish a real effect from a lucky seed.
The epoch-2 checkpoint may generalise comparably to epoch 3; this was not tested.

**What remains valid.** The base-vs-tuned gap is large enough (format 30.0% → 100.0%,
ROUGE-L 0.2416 → 0.5104) that it is unlikely to be seed noise. Both variants used
identical prompts, decoding, and seed, so the comparison is internally controlled.

---

## 7. Grounding did not improve with fine-tuning

**Evidence.** Reports free of invented entities: **95.0% base, 95.0% tuned** — unchanged.
The ungrounded *entity* rate slightly regressed, 2.1% → 3.4%, because the tuned model
names more entities per report (`EVAL_RESULTS.md`).

**What it limits.** The project cannot claim fine-tuning reduces hallucination. The
grounding metric was a primary claim in `SCOPE.md` §5.1, and on this axis the result is
flat.

**What remains valid.** The tuned model *is* well grounded in absolute terms, and the
reference corpus it learned from is clean — only 2 of 400 reference reports contain an
ungrounded entity, both directory prefixes of paths that are present rather than invented
locations (`DATASET_STATS.md` §5). The honest statement is that the base model was
already mostly grounded and there was little headroom to learn from.

---

## 8. RAG was scoped but never implemented

**Evidence.** No retrieval step exists in any script, notebook, or result. The originally
planned third evaluation arm (fine-tuned + RAG) was not built.

**What it limits.** Any claim involving retrieval. The ATT&CK corpus is used only to
validate IDs and names in the lookup table.

**What remains valid.** The two-arm comparison actually run — base vs fine-tuned — is
complete and self-contained.

---

## Summary: the defensible claim

> A 3B parameter model, adapted with a 4-bit QLoRA adapter on 360 synthetic examples, can
> be taught to produce structured six-section incident reports with 100% format adherence
> and substantially higher similarity to reference reports than the unadapted base model
> (ROUGE-L 0.2416 → 0.5104; BERTScore 0.8150 → 0.9102), while remaining as well grounded
> in its input as the base model.

Everything beyond that sentence needs a caveat from the list above.
